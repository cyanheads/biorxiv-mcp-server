# 0.4.1 — 2026-10-17

## Changed

- **Call budget** — every upstream retry ladder in `biorxiv_get_preprint`, `biorxiv_get_published_version`, `biorxiv_get_fulltext`, `biorxiv_search_preprints`, `biorxiv_list_recent`, and `biorxiv_list_published_versions` draws on one 50 s budget per tool call, chained requests included. A step that runs out of it fails with the tool's retryable upstream reason, or degrades where the tool already degrades; the budget never aborts the caller's signal (#64).
- **`biorxiv_get_fulltext` article page** — a page that does not answer within the budget raises `upstream_unavailable` instead of a bare timeout (-32004) (#64).
- **DOI lookups** — with `server: "both"`, a lookup for one DOI ends when the server holding it answers and cuts the other lookup short, so a stalled server that lacks the DOI no longer spends the call's budget (#64).
- **`biorxiv_get_preprint` `dois`** — accepts up to 200 entries. The first 10 distinct DOIs are looked up and the rest return in the new `unprocessed` array with an enrichment notice. An unparseable entry goes to `failed[]` wherever it sits, a repeated DOI is looked up once, and all lists keep input order; batch-level errors raise only when nothing resolved and `unprocessed` is empty (#63).
- **`biorxiv_search_preprints` `limit`** — a value above 100 returns the first 100 results with a notice and the truncation fields; `nextCursorMark` continues the list. The schema ceiling is 1000 (#69).
- **`biorxiv_list_published_versions` `limit`** — new input (default 25, up to 1000) sets the rows returned per server, sliced from the start of the upstream page. `nextCursor` advances by the rows served; `limit: 100` returns the previous full page, and a larger value returns 100 with a notice. The default page is now 25 rows per server (#68).
- **Minor:** the `preprintDate` description on `biorxiv_list_published_versions` rows notes that medRxiv lists some `10.64898/` preprints on two rows that differ in that date.

## Fixed

- **Cancellation** — `biorxiv_get_preprint`, `biorxiv_list_recent`, `biorxiv_get_published_version`, `biorxiv_search_preprints`, and `biorxiv_get_fulltext` rethrow a caller cancellation (-32011) instead of recording the aborted leg as a failed lookup or returning a partial result (#65).
- **Service test assertions** — the three HTML-error tests in `BiorxivApiService` and the full-text 5xx test assert the classified error, so removing their guards fails them (#66).
