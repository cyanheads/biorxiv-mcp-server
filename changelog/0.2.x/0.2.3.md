# 0.2.3 — 2026-08-09

## Added

- **`biorxiv_search_preprints`** — enriched results now carry `type`, `license`, `funder`, and `authorCorrespondingInstitution` from the latest revision, in the output schema, `structuredContent`, and `format()` — the same latest-revision fields `biorxiv_get_preprint` returns. Full revision history stays out of search; `revisionCount` plus `biorxiv_get_preprint` remains the detailed-history workflow. [#33](https://github.com/cyanheads/biorxiv-mcp-server/issues/33)
- **`rate_limited` reason** added to the `biorxiv_get_preprint`, `biorxiv_get_published_version`, and `biorxiv_list_recent` error contracts, each carrying `retryAfter` when the origin's `Retry-After` was usable. [#41](https://github.com/cyanheads/biorxiv-mcp-server/issues/41)
- **`biorxiv_search_preprints`** — new `enrichment_error: 'rate_limited'` value distinguishes an origin 429 from a generic `service_error` on a degraded enrichment. [#41](https://github.com/cyanheads/biorxiv-mcp-server/issues/41)

## Changed

- **`BiorxivApiService.getDetails` / `getListing` / `getPublishedVersion`** — HTTP 429 from `api.biorxiv.org` is now classified as a retryable `rate_limited` error whose payload is rebuilt from scratch (`{ reason, retryable, retryAfter?, recovery }`); the upstream response body no longer reaches the caller. No retry or backoff logic was added — `withRetry` already honors `Retry-After`. [#41](https://github.com/cyanheads/biorxiv-mcp-server/issues/41)
- **`parseRetryAfterSeconds`** moved from `BiorxivFullTextService` into `services/shared.ts`, joined by `findRateLimit` (reduces a set of rejections to the longest reported wait) and `describeWait`. [#41](https://github.com/cyanheads/biorxiv-mcp-server/issues/41)
- **`biorxiv_list_recent`** — raises a retryable `upstream_unavailable` (or `rate_limited`) error when every attempted server fails under `server="both"`, instead of returning a successful empty listing with a notice. The partial-failure case — one server failing, the other's page returned — is unchanged. [#40](https://github.com/cyanheads/biorxiv-mcp-server/issues/40)
- A rate limit now outranks a generic upstream failure wherever an all-failed branch can mix the two — `biorxiv_get_preprint`, `biorxiv_get_published_version`, `biorxiv_list_recent`, and `biorxiv_get_fulltext`'s version-resolution step all raise `rate_limited` over `upstream_unavailable` when a 429 is among the rejections. [#41](https://github.com/cyanheads/biorxiv-mcp-server/issues/41)
- Service-level tests now drive the real `BiorxivApiService` 429 rejection via a shared `tests/helpers/rate-limit.ts` fixture, so the tool suites' mocked shape cannot drift from what the service actually throws.

## Fixed

- **`biorxiv_get_fulltext`** — the rate-limit recovery hint no longer recommends `biorxiv_get_preprint` as a working fallback when that tool's own metadata origin (`api.biorxiv.org`) is the one rate-limiting; it now reads the version-resolution rejections and reports the longer of the two waits.
- **`biorxiv_search_preprints`** — the two overlapping enrichment-failure flags collapsed into a single rejection list, fixing a case where an upstream outage or rate limit was mislabelled `not_found`.
