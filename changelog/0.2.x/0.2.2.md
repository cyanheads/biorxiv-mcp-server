# 0.2.2 — 2026-08-09

## Added

- **`biorxiv_get_fulltext`** — `server` input gains `"both"` and now defaults to it, resolving the DOI across bioRxiv and medRxiv via `Promise.allSettled` (the shared `10.1101/` prefix does not identify the server). Only DOI resolution fans out; the full-text fetch still targets the single server that answered. A new retryable `upstream_unavailable` reason covers the all-rejected case. [#38](https://github.com/cyanheads/biorxiv-mcp-server/issues/38)
- **`biorxiv_get_fulltext`** — HTTP 429 from the full-text origin is now classified as its own retryable `rate_limited` reason, carrying the parsed `Retry-After` wait (RFC 9110 §10.2.3, both delta-seconds and HTTP-date forms) and a recovery hint pointing at `biorxiv_get_preprint`. The Cloudflare block page's HTML no longer reaches the response payload. [#37](https://github.com/cyanheads/biorxiv-mcp-server/issues/37)

## Changed

- **`BiorxivFullTextService.fetchFullText`** — the extracted article is now cached in tenant-scoped `ctx.state` under `fulltext/v1/{server}/{doi}/{version}` for one hour, so `offset` paging and the `offset_out_of_range` check serve from the cache instead of refetching and re-extracting the origin per call. Cache reads and writes are fail-soft (a storage failure logs a warning and falls through to the origin); `blocked`/`empty`/`rate_limited` results are never cached, and the cache is skipped without a tenant. [#36](https://github.com/cyanheads/biorxiv-mcp-server/issues/36)
- **`fetchWithTimeout`** call in the full-text service now passes `expectedStatuses` for the deterministic-unavailable set plus 429, logging those responses at `debug` instead of `error`. Status reads moved from the legacy `data.statusCode` alias to canonical `data.status`.

## Fixed

- **`BIORXIV_WEB_BASE_URL`/`MEDRXIV_WEB_BASE_URL`** — read by the config and documented in the README but never declared in `.env.example`, `server.json`, or `manifest.json`. Added to all three. `src/config/server-config.ts` now guards both with the existing MCPB-placeholder strip, so an unsubstituted `${user_config.X}` literal falls back to the default instead of failing URL validation at startup.
