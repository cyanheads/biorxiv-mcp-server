# 0.2.4 — 2026-08-09

## Changed

- **`EuropePmcService.search`** — HTTP 429 from EuropePMC is now classified as a retryable `rate_limited` error carrying the parsed `Retry-After` wait, mirroring `BiorxivApiService`: `expectedStatuses: [429]` on the fetch, classification outside `withRetry`, and a payload rebuilt from scratch so the upstream response body never reaches the caller. [#42](https://github.com/cyanheads/biorxiv-mcp-server/issues/42)
- **`biorxiv_search_preprints`** — gained a `rate_limited` error-contract entry for the EuropePMC search path; its recovery hint names the wait and states the scope of the limit rather than promising `biorxiv_list_recent` will answer, since the search runs first and establishes nothing about `api.biorxiv.org`. The enrichment path is unchanged and still degrades to EuropePMC-only metadata on a 429. [#42](https://github.com/cyanheads/biorxiv-mcp-server/issues/42)

## Fixed

- **`docs/design.md`** — error-contract table corrected three rows citing `InvalidParams` where the source throws `ValidationError`, added two missing rows, removed a resilience-table row contradicting the one beneath it, and corrected an overclaim that every origin sends `Retry-After`.
- **`EuropePmcService` test suite** — two HTML-error-page tests asserted only `.rejects.toThrow()` over a mock shape the real service never produces; they now assert the classified error code, so removing the HTML-error guard fails the tests instead of passing.
