# 0.1.4 — 2026-05-23

Seven bugs found in field-testing, all affecting core functionality.

## Fixed

- **DOI encoding** — `biorxiv-service.ts` now encodes DOI segments individually (`doi.split('/').map(encodeURIComponent).join('/')`) instead of calling `encodeURIComponent` on the full DOI string; the slash separating prefix and suffix was being double-encoded, causing all lookups to 404.
- **Funder field** — `normalizeRevision` now handles `funder` as either a plain string or an array of `{ name, id, award }` objects; previously, an array payload would surface as `"[object Object]"`.
- **Pagination total** — `messages[0].total` is a string in real API responses (e.g. `"915"`); `parseInt` now parses it correctly. Was always 0 before this fix.
- **EuropePMC server filter** — `biorxiv-search-preprints` now uses `PUBLISHER:bioRxiv` / `PUBLISHER:medRxiv` field syntax instead of `PUBLISHER:"Cold Spring Harbor Laboratory"`, which is not a valid EuropePMC field and returned no results.
- **Date validation** — `biorxiv_search_preprints` now validates `date_from` and `date_to` against `YYYY-MM-DD` format before calling EuropePMC; invalid dates were previously passed through silently and returned 0 results.
- **User-Agent** — `EuropePmcService` no longer emits `mailto:undefined` in the `User-Agent` header when `BIORXIV_MAILTO` is unset; the mailto segment is now omitted entirely when the env var is absent.
- **DOI prefix** — `BIORXIV_DOI_PREFIXES` expanded to include `10.64898/` (new bioRxiv prefix introduced in 2025); papers under this prefix were being misidentified as medRxiv and enriched against the wrong server.
