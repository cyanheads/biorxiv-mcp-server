# 0.3.0 — 2026-09-22

## Added

- **`funder` filter on `biorxiv_list_recent`** — a ROR id, normalized and checksum-checked before any call. bioRxiv-only: narrows `server="both"` to bioRxiv and raises `invalid_funder` for `server="medrxiv"` or an id `api.biorxiv.org` holds no record for ([#52](https://github.com/cyanheads/biorxiv-mcp-server/issues/52)).
- **`include_abstract`** on `biorxiv_list_recent` (default `false`) and `biorxiv_search_preprints` (default `true`) — drops the abstract from `structuredContent` and `content[]` together, no other field changes. Callers reading `abstract` from `biorxiv_list_recent` must now pass `include_abstract: true` ([#49](https://github.com/cyanheads/biorxiv-mcp-server/issues/49)).
- **`biorxiv_search_preprints` fallback abstracts** — a record that falls back to EuropePMC metadata now gets its abstract from one DOI-keyed `resultType=core` lookup (`EuropePmcService.getAbstracts`); a failed lookup degrades like enrichment, with a notice ([#55](https://github.com/cyanheads/biorxiv-mcp-server/issues/55)).
- **`normalizeUpstreamText`** resolves Highwire symbol placeholders and fused section headings through closed tables in `upstream-text-tables.ts`, renders `O_ST_ABS` headings and `O_LI` list items as plain text, and drops table blocks (`O_TBL`) alongside existing figure handling. `escapeMarkdown` escapes upstream text at `format()` interpolation so `content[]` renders it literally ([#48](https://github.com/cyanheads/biorxiv-mcp-server/issues/48)).

## Changed

- **`awards: string[]`** replaces `funder` on `biorxiv_get_preprint`, `biorxiv_list_recent`, and `biorxiv_search_preprints` — upstream funder `name`s and ROR `id`s are misattributed to unrelated organizations, so only the verbatim, deduplicated `award` values are kept. Callers reading `funder` must switch to `awards` ([#54](https://github.com/cyanheads/biorxiv-mcp-server/issues/54)).

## Fixed

- **`normalizeUpstreamText` inline-tag stripping** no longer splices a tag together from the text around a removed one: `<scr<i>ipt>` stays as sent instead of becoming `<script>`.
